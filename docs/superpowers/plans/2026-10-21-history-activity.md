# History, Activity and Chat Approval Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for bounded protocol/UI packets and superpowers:executing-plans for parent integration. The user requested history selection, tool activity, summaries and explicitly chose an optional per-chat automatic edit approval switch, default off.

**Goal:** Reopen persisted Aseprite conversations, see tools and supplied reasoning summaries, and explicitly allow edits for one chat without repeated confirmations.

**Architecture:** Codex owns thread persistence and protocol state. The Lua client pages stored threads/turns and emits reasoning items. The native view owns only selection and transcript presentation. The controller owns the temporary approval mode and local tool execution lifecycle; one stateless timeline module projects live/history activity into the same display shape. No second history store, global Aseprite trust edit, remote transport or extra service is introduced.

**Tech Stack:** Aseprite 1.3.18.6 Lua, installed Codex 0.163.0 schema (work/app-schema), existing Node bridge and ws runtime.

## Contracts

- `codex.lua`: `list_threads({cursor?,search?}, callback(page,errorText))`, returning `{data={id,name?,preview,updatedAt,status},nextCursor?}` with only `originator == "aseprite_chat"` entries. Request sourceKinds cli/vscode/appServer explicitly and filter originator locally (local app-server rejects nonempty originators filters). Each request is one page; native picker can load more. `open_thread(id,callback(result,errorText))` works only while initialized/idle, enters loading, verifies thread/read originator and inactive status, resumes with current Aseprite developer instructions/read-only sandbox/user review, then loads full turn items using paginated thread/turns/list ascending. It never executes historical tools or interrupts a thread active in another editor. Commit the selected binding only on success, return `{thread,turns}`; ordinary failures preserve the prior displayed conversation. New operations retain generation cancellation rules.
- `codex.lua`: existing agent on_message callback stays. New `on_item(item,completed)` emits non-agent item updates and reasoning summary updates. Summary deltas use summaryIndex, preserve section ordering, and completed reasoning.summary replaces accumulated summaries; raw reasoning.content/textDelta is not displayed. Optional send settings.summary snapshots the supplied summary mode (auto only for reasoning-capable selections).
- `chat.lua`: History button opens one modeless compact picker with search, native thread combobox, Open/Refresh/More/Done. `callbacks.on_list_threads(search,cursor,callback)` returns a page through callback(page,errorText); `on_open_thread(id)` returns started,errorText. Picker validates dialog identity and request serial before applying async results, disables opening during turns, appends pages and handles empty results/errors. Closing main closes picker. `set_approval_mode(enabled)` projects controller state to settings check and main status; checkbox callback `on_approval_mode(enabled)` returns accepted,errorText. The checkbox is default off, enabled only while idle, and not persisted. Settings remains left-aligned and fits visible content.
- `main.lua` and new `timeline.lua`: one controller auto_approve boolean, reset by New Chat, successful explicit thread selection and close. Disconnect/reconnect retains it for the same open chat. Auto/manual approval use the same single-use completion path and immediate revision/turn revalidation. All read/edit attempts show keyed tool status, summary/code and bounded textual results without PNG/base64 dumps; pending edits become canceled on stop/loss. Timeline projections support persisted user/assistant/reasoning/dynamic tool/plan items, omit raw hidden reasoning, and remove the client's appended canvas context from displayed user prompts. No historical item invokes an executor.
- Aseprite native full trust remains an explicit user decision in its own permission dialog. Document that it is stored by Lua filename, so modules can need separate grants. Plugin auto-approval is a separate in-memory decision for captured-sprite edits.

## Runtime-driven revisions

Real Codex 0.163.0 list requests with the original updated_at/source parameters exceeded 90 seconds on the default scan-and-repair path. The supported `useStateDbOnly=true` parameter returned the same persisted target in 0.5–0.7 seconds; list requests now query Codex's index directly while preserving sort and pagination. The host's `CODEX_INTERNAL_ORIGINATOR_OVERRIDE` also overrode initialize.clientInfo.name. The bridge scopes that environment value to `aseprite_chat` for its child only, making durable ownership independent of the launch host. Readiness/discovery version 2 prevents automatic reuse of older bridge processes that lack that contract. No global environment or Codex/Aseprite configuration is changed by the product.
