# Local Aseprite MCP Implementation Plan

**Goal:** Let an external Codex control the running Aseprite editor and let the plugin register its MCP server in the explicitly selected Codex home.

**Architecture:** Keep the existing internal chat. Reuse Executor through a separate native MCP control session. A per-home Node loopback hub connects one Aseprite editor to multiple stdio MCP clients; the official MCP SDK handles the host-facing protocol. Shared `tools.json` owns the five existing tool definitions. Registration uses the native Codex CLI under the selected `CODEX_HOME`, with configuration backup and collision checks.

**Tech stack:** Aseprite Lua, Node 24, ws 8.22.0, MCP SDK 1.32.1, Windows PowerShell 5.1.

## Contracts

- `scripts/mcp-bridge.mjs`: exports `ensureBridge({home, extensionRoot})`, returning `{endpoint}` for an editor websocket. Descriptor: `<home>/.aseprite-chat/mcp-bridge.json`. Stdio clients use an authenticated client endpoint from the same descriptor. Loopback only, random capability token, browser/Fetch/foreign Host rejection, one editor, distinct client IDs, one active operation globally, bounded timeout/cancellation.
- Hub editor wire: `{type:"call",id,clientId,tool,arguments}`, `{type:"cancel",id}`, `{type:"client_closed",clientId}`. Editor replies `{type:"result",id,result:{success,contentItems}}`. The hub owns client/request identity; models cannot choose client IDs.
- `scripts/mcp-server.mjs --home <absolute-home>`: SDK stdio server, canonical tools loaded from `tools.json`, native PNG data URLs mapped to MCP image content, errors mapped to `isError`. No model/account login or app-server subprocess.
- `scripts/register-mcp.mjs --home <absolute-home> --root <extension-root> --result <owned-result-path> [--connect-only]`: find native Codex, back up the selected config, refuse foreign `aseprite_chat` registration collisions, use `codex mcp add aseprite_chat -- <native-node> <installed-root>/scripts/mcp-server.mjs --home <home>`, verify with `get --json`, then ensure hub and atomically publish `{endpoint}` or `{error}`. Connect-only never changes config. Child environment sets CODEX_HOME only; API credentials never copied.
- `scripts/mcp-launch.ps1`: hidden bootstrap for the register helper. Lua Launcher accepts explicit script/parameters for this existing asynchronous launch mechanism.
- `mcp.lua`: standalone native panel, home entry defaulting to the currently selected account home, Register & connect / Connect / Disconnect. Per-client Executor observations, native approve-once edit dialog, stale revision checks before and after approval, no automatic edits. Client cancellation/disconnect retires callbacks; no historical execution/replay. Reads inspect the live active context before default-target reads. Source reads/edits/exports run only in Aseprite.
- Current editing target and exports belong to each connected MCP client. Multiple clients have isolated captured revisions; only one operation runs globally. Closing/disconnecting the control session retires all local operations and cleans its owned artifacts. Existing internal chat remains independently usable.
- No GUI editor or real model calls for tests; use isolated homes, real MCP SDK clients and batch Aseprite fixtures. Preserve user config/preferences. Registering into a real home happens only through the explicit plugin action; development tests never alter real homes.

## Work packets

1. Parent: canonical tools migration, Launcher extension, native control panel and menu integration, native controller tests.
2. Node worker: hub/stdio MCP transport and SDK integration tests, including real wire, images, multiple clients, busy/cancel/disconnect/late results and owned daemon lifetime.
3. Registration worker: native CLI registration/bootstrap and isolated-home tests, preserving unrelated config, idempotency, collision handling and Unicode/special-character paths.
4. Parent: complete end-to-end native batch fixture through SDK host, focused regressions, independent review, package 0.5.0, backup/hash install and local commit. No push/merge.
